# AntiSentinel 五项能力实现设计

## 目标与约束

按用户给定的 Runtime、分层记忆、Skill、代码 RAG、多意图 DAG 五项标准补齐现有实现并提供可复现验收。源码核验见 `docs/research/2026-10-23-open-source-runtime-verification.md`。
Python >=3.11，保持 Domain 与外部系统隔离，模型只产出计划，代码控制权限和调度。延续现有 Runtime/SQLite/Redis/Milvus/OTel，不引入新的 Agent 框架，不覆盖原始评测记录。

## 方案选择

采用增量扩展：保留已有 Agent Turn 循环，DAG 作为计划执行层，与 Runtime 通过 ToolExecutor、Evidence 交互。相比重写整套 Runtime，这条路径保留现有上下文与恢复契约，代价是计划执行与自由推理分别拥有清晰的生命周期。
不将既有每个模型 Turn 强制编译成 DAG；不把五套开源项目作为依赖。上游机制是设计依据，而不是复制上游业务代码。

## DAG 契约

- PlanningService 接受可选的 `step_id`、`depends_on`，老格式仍有效；没有声明依赖的旧计划保留原有顺序，显式声明空依赖的节点可以并行。
- 执行前冻结计划定义并计算哈希，校验节点唯一、依赖存在、无环、参数和真实工具目录匹配。
- 有界线程池运行已就绪节点；依赖全部成功才执行，失败阻断其后代而不阻断无关分支。
- 节点开始与结束均同步持久化；同一执行租用独占运行锁。恢复复用成功结果；读工具可重试，进程中断的写工具进入人工核对，不自动重放。
- 恢复绑定工具 Python 代码身份及可选 implementation_version；远程协议和闭包配置变更须显式更新版本。未知快照 schema 拒绝恢复。
- 执行时重新核验允许工具与只读限制；计划里的 `read_only` 声明不能代替注册表权限。
- 新的显式执行入口运行已有持久化草案，校验 actor/session、版本与计划哈希；规划和执行不是同一个请求。
- OTel 连接计划与节点，证据与工具结果随节点状态归档；取消后停止提交新任务，在运行的线程协作结束后记录最终状态。

## 其余四项

保留已有实现，通过统一验收入口运行对应的上下文压力、Checkpoint、记忆隔离/冲突、Skill Release/权限、代码检索/来源一致性回归。按源码核查中发现的具体缺口补实现，不以重新命名骨架代替功能。
效果报告单独检查数据规模、基线、延迟口径、Recall/MRR 和未完成项；无数据或真实模型运行时明确标为未评测。

## 风险与验证

外部写入和本地落盘之间无法构成分布式事务，不能承诺一次且仅一次；对不确定写入暂停核对。线程不能被强制安全终止，取消是协作式。预算测试证明本地计数器的上限，真实服务商 tokenizer 仍需单独核验。
使用 Barrier/Event 证明并发和依赖次序，SQLite 重开证明恢复，跨进程锁证明互斥；非法依赖、内容篡改、失败传播、写权限绕过和跨用户执行均须被拒绝。
